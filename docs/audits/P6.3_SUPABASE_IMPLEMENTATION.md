## Purpose

P6.3 is the canonical working register for unresolved Reference backend behavior and its implementation.

P6.3 is intentionally **not** a one-shot “create the approved tables” batch. The lifecycle is:

Reference audit → add/update canonical row → target decision → implement in the correct layer → verify → re-audit

A newly discovered Reference surface is added as a row here. The row then determines whether the implementation belongs in:

- Supabase;
- Android/app code;
- both Supabase and app;
- CloudProviderRepository / external-provider boundary;
- **DO NOT MODEL**;
- **UNKNOWN / further audit required**.

This keeps P6.3 as one evolving source of truth and avoids creating a new phase or document for every finding.

## Status vocabulary

- **AUDIT REQUIRED** — Reference behavior is known to exist, but the field-complete target contract is not yet safe to implement.
- **DEFINED** — Target owner and contract are sufficiently bounded for implementation.
- **IMPLEMENTED** — Target code/schema has been changed.
- **TESTED** — Target behavior has been exercised by an appropriate test.
- **VERIFIED** — Evidence proves the required behavior at the current verification boundary.
- **UNKNOWN** — Evidence is insufficient; do not assume.
- **DEFERRED** — Explicitly held because an upstream dependency or contract is not yet resolved.
- **DO NOT MODEL** — Reference evidence exists but the target architecture intentionally does not reproduce that mechanism.
- **NOT REQUIRED** — Contract/audit establishes that no target implementation is needed.

IMPLEMENTED ≠ VERIFIED.

## P6.3 working rule

When a new Reference finding appears:

1. **Audit the Reference evidence.**
2. **Add or update one canonical register row.**
3. **Define the owner/boundary.**
4. **Choose the target decision.**
5. **Implement in Supabase, app, both, provider boundary, or nowhere as justified.**
6. **Verify at the strongest currently authorized boundary.**
7. **Re-audit the row and update its status/evidence.**

Do not create a new phase or a new audit document solely because a new backend finding appears.

## P6.3 exit criteria

P6.3 can close only when the canonical register has no unresolved item that blocks the P6 backend contract, and each applicable row has:

- Reference evidence;
- owner/boundary;
- target decision;
- implementation status;
- verification result or explicit verification limitation;
- downstream dependency recorded where applicable.

P6.3 closure still does **not** equal APK/runtime verification. P7 owns runtime/device validation.
