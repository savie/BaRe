## F24 static re-audit

Primary ZIP evidence:
- `StorageSwitchActivity` selects a `zn7` volume and displays `StorageInfoLocal.Success`, filesystem type and root requirement.
- `zn7` exposes filesystem type detection, read/write/root requirement and Android `StorageVolume` integration.
- `no7` checks destination usable space against current Swift Backup footprint, detects existing destination files, and exposes COPY/MOVE/DO_NOTHING choices.

BaRe now statically maps these into:
- `AndroidStorageInventory` → Android `StorageManager/StorageVolume` inventory plus filesystem type/read-write/root state.
- `StorageBackupFootprint` → current `SwiftBackup` footprint measurement.
- `StorageSwitchTransition` → destination availability/space and existing-destination decision algebra.
- `StorageMigrationPlan` + `StorageMigrationExecutor` → explicit handoff to the concrete filesystem migration owner without executing it in P5.5.
- `StorageSwitchActivity` → actual preflight/routing consumer rather than a UI-only boundary.

F89 remains the owner of the reusable storage measurement/snapshot contract; F125 remains the generic disk-space/reclaim boundary. No duplicate F-ID was introduced.

## F84 static re-audit

Primary ZIP evidence:
- `MDatabase_Impl` registers `SMessage`.
- `SMessage` schema is `time INTEGER NOT NULL`, `messageType INTEGER NOT NULL`, `title TEXT NOT NULL`, `msg TEXT NOT NULL`, `color TEXT`, `id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL`.
- `kv6/nv6` expose insert, latest retrieval, after-time observation, count, delete-all and delete-older-than.
- Latest retrieval is limited to the newest rows and then ordered ascending; after-time query uses `time > ?`.

BaRe now statically maps these into:
- `SLogDatabase` with the Reference-shaped `SMessage` table.
- `SLogRepository` with the same core DAO operation set, 10,000-row cap, three-day retention and observer callback boundary.
- `SLogActivity` consuming F84 repository state while remaining F35 presentation owner.

No Room runtime/database verification was performed, and no provider/backend delivery was introduced.
