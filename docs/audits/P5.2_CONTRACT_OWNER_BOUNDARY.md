# FIELD MINIMUM

Setiap feature cukup dibaca lewat 7 hal:

| Field | Isi |
|---|---|
| **F-ID** | ID dari P5.1 |
| **Owner** | component/domain yang benar-benar memiliki responsibility |
| **Boundary** | tanggung jawab yang dimiliki |
| **Consumer** | siapa yang memakai contract |
| **Dependency** | contract/feature yang dibutuhkan |
| **Target** | lokasi BaRe yang akan menjadi target |
| **Status** | 🟢 BOUNDED / 🟡 CONSOLIDATING / 🔴 UNKNOWN / 🔵 DEFERRED |

Tidak perlu menyalin ulang seluruh forensic evidence ke P5.2.  
Evidence detail tetap berada di P5.1.

---

# OWNER RULE

1. Activity bukan otomatis owner.
2. Repository/service/domain/task menjadi owner bila evidence menunjukkan responsibility di sana.
3. UI boleh menjadi owner hanya bila memang UI memiliki contract tersebut.
4. Satu contract tidak boleh mempunyai dua canonical owner.
5. Provider/backend tetap berada di belakang boundary yang sudah ditentukan.
6. Jangan membuat owner baru hanya karena menemukan class baru.

---

# STATUS RULE

### 🟢 BOUNDED
Owner dan boundary sudah jelas.

### 🟡 CONSOLIDATING
Evidence sudah ada di P5.1, tetapi matrix P5.2 belum selesai dirapikan.

### 🔴 UNKNOWN
Evidence belum cukup untuk menentukan owner/boundary.

### 🔵 DEFERRED
Boundary sudah jelas, tetapi eksekusinya memang milik phase/downstream lain.
