## Canonical ownership model for Phase 6

Use this ownership chain when implementing the backend later:

`UI/feature consumer → provider-neutral domain/repository boundary → Supabase adapter → Supabase service/backend`

For identity:

`Account lifecycle → provider-neutral BackendIdentity → Supabase Auth identity`

For cloud backup providers:

`BaRe account/backend identity ≠ external cloud-provider identity`

`CloudProviderRepository` owns external backup-cloud access. Supabase owns BaRe backend concerns. They must not be collapsed into one credential or repository model.

## Data classification for P6

Every persisted/transported value should be classified before Supabase implementation:

- **LOCAL_ONLY** — device state that remains local.
- **LOCAL_PERSISTED** — preferences/database/config persisted on device.
- **CLOUD_PERSISTED** — BaRe-owned data intentionally stored in Supabase.
- **BACKEND_DERIVED** — data returned/derived by BaRe backend services.
- **PROVIDER_DERIVED** — state belonging to Google Drive/Dropbox/etc.
- **RUNTIME_ONLY** — transient execution state.
- **SECRET/CREDENTIAL** — tokens, private keys, passwords, encryption material, or equivalent.
- **MIXED_LOCAL_CLOUD** — state whose local and backend representations must be reconciled explicitly.

No field is assigned to a Supabase table merely because the Reference stored it remotely.

## Credential handling rule

Reference evidence contains credential-shaped contracts in R-D (for example token/session/private-key fields). These are **contract shapes, not authorization to persist secrets in Supabase**.

P6 must explicitly classify each credential as one of:

- NEVER_BACKEND
- LOCAL_SECURE_STORAGE
- SUPABASE_AUTH
- SUPABASE_DATABASE
- EXTERNAL_PROVIDER_ONLY
- TRANSIENT_MEMORY

Default rule for P6: do not put provider secrets, private keys, encryption keys, passwords, or access/refresh tokens into ordinary application tables unless a later evidence/authorization decision explicitly requires it.

## Reference backend contract quarantine

`ReferenceBackendContract` records Reference path evidence such as `users/{uid}/userInfo`, `cloud_v1`, and purchase-verification paths.

Audit finding:

- It has no application consumer.
- It is useful as evidence.
- It must remain **Reference evidence**, not become a literal Supabase schema.
- P6 should derive the Supabase data model from the BaRe requirements and approved target policy, then map only the required semantics.

This prevents accidental Firebase-shaped schema reconstruction.
